# Maintainers

This document defines who maintains Scrum Pilot, the expectations for maintainers, and how maintainers are selected or rotated.

## Purpose

Maintainers are responsible for keeping the project healthy, secure, and welcoming for contributors.
They review changes, guide roadmap decisions, and enforce project standards.

## Maintainer Rules

All maintainers are expected to:

1. Follow the project Code of Conduct at all times.
2. Review pull requests fairly, consistently, and with actionable feedback.
3. Prioritize security, reliability, and readability over speed.
4. Keep changes small and reviewable whenever possible.
5. Require passing CI and relevant tests before merging.
6. Avoid merging their own major changes without at least one independent review.
7. Disclose conflicts of interest in decisions that may affect impartiality.
8. Respond to issues and pull requests in a reasonable timeframe.
9. Tag or involve domain owners when reviewing unfamiliar areas.
10. Help onboard contributors and document decisions that affect the project.
11. Protect secrets and sensitive data; never commit credentials.
12. Escalate urgent production or security concerns immediately.

## Maintainer Responsibilities

Maintainers share responsibility for:

- Reviewing and merging pull requests.
- Managing issue triage and labels.
- Keeping documentation current.
- Supporting release readiness and change logs.
- Enforcing contribution and testing expectations.
- Coordinating incident response when needed.

## How Maintainers Are Selected

Maintainers are selected through the following process:

1. Nomination:
A candidate is nominated by an existing maintainer or by project consensus in a public thread.

2. Eligibility check:
The candidate should typically demonstrate:
- Sustained, high-quality contributions.
- Constructive code review behavior.
- Good communication and collaboration.
- Familiarity with the project architecture and standards.

3. Maintainer vote:
Existing maintainers vote publicly or in a recorded decision thread.
A simple majority approves unless the team defines a stricter rule.

4. Trial period:
The candidate serves as a probationary maintainer for 30-90 days with scoped permissions.

5. Confirmation:
At the end of the trial period, maintainers confirm the appointment and update this file.

## Maintainer Removal or Inactivity

A maintainer may be moved to inactive or removed status when:

- They request to step down.
- They are inactive for an extended period (for example, 90+ days with no maintainer activity).
- They repeatedly violate project policies or code of conduct.
